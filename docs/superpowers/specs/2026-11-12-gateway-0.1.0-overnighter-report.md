## Decisions made without Chris

Each with the options I saw and why this one (decision rules: breaks nothing, true to Kumbu², opens no hole, true to the spec).

1. **MongoDB needs a replica set: yes.**
   - Options: single-document atomic updates only; a replica set for transactions.
   - Code exchange, refresh rotation, consent and revocation each write several documents that must change together. Kumbu²'s token code relies on transactions; porting it as is was safer than re-deriving it without them.
   - Compose initiates `rs0` in MongoDB's health check, as Kumbu² does.
2. **The Traefik variant is included,** as `compose.traefik.yaml` modelled on Kumbu²'s, optional (the brief's call). Komogentic reaches Komodo through the proxy network unless an override adds an internal one, which the README recommends.
3. **The verdict rules:**
   - **Stack states:** `deploying` and `created` are yellow; `running` and `unhealthy` are judged per service; `restarting` is red (Komodo sets it only when every container is in Docker's restart loop); every other state is red.
   - **Services, red:** `(unhealthy)`, `Restarting`, `Exited (n≠0)`, `Dead`, `Paused`, `Stopping`, `Removing`, `Down`, `Unknown`, and Swarm `Unhealthy`.
   - **Services, yellow:** `(health: starting)` and `Created`.
   - **Services, not counted:** `Exited (0)` counts as "completed", for migrations and other one-off jobs. Services in `ignore_services` don't count.
   - **Stack-wide red:** `missing_files`, and `project_missing` unless the stack is down or deploying (as Komodo's own UI).
   - Options: state only; state plus health. Health matters for "is it green?", so `list_stacks` also reads services for running and unhealthy stacks.
4. **Default wait of `deploy_stack`/`restart_stack`: 50 s.**
   - Options: the spec's 10 min; clients' timeouts. The MCP TypeScript SDK's default request timeout is 60 s, and most clients keep it.
   - 50 s answers before that, with "still running, update id …" when the wait is reached. `wait_seconds` goes up to 600 for clients with longer limits (Claude Code).
   - Logged once at start-up.
5. **Komodo's errors** are classified by message, not by HTTP status:
   - Not-found and no-permission are both HTTP 500, an expired JWT is a 500 too ("Invalid user credentials"), and a missing Execute appears as a failed update with a `Task Error` log.
   - Only Komodo's own credential messages count as "key rejected"; a bare 401 (a proxy) doesn't.
6. **Unknown and invisible stacks** get the same answer, "no such stack: X (or your Komodo user may not see it)". Deploy and restart call `GetStack` first, because Komodo accepts an execution on a stack the user can't see and fails it only later.
7. **Log search:**
   - Terms are sent literally and case-insensitively, as bracket pairs (`[eE]`), metacharacters escaped and `-` as `[-]`. Komodo pipes the last 5000 lines through `grep -E` (any term) or `grep -P` (all terms), case-sensitive (`bin/periphery/src/helpers.rs:117`).
   - Checked with a real GNU `grep` in a test.
   - A search with no matches (grep's exit 1) is "(no line matches)", not an error.
8. **Swarm stacks:** the same calls; logs need exactly one service (Komodo's rule); searching their logs is refused with an explanation, because Komodo 2.3.4's `SearchStackLog` passes the bare service name to the swarm (`bin/core/src/api/read/stack.rs` ~361). Their verdict is untested; the README says so.
9. **The session's JWT** is sealed with AES-256-GCM under `HKDF(cookie secret, "kgt/v1/session-jwt")`, bound to the user (the brief's settled point).
   - The session lasts 30 min idle and 12 h at most, never past the JWT's `exp` (milliseconds in Komodo's claims).
   - The cookie is `kgt_session`, `Path=/api`, HttpOnly, Secure, SameSite=Strict. A request with two such cookies is refused (cookie tossing from a sibling subdomain).
10. **A credential whose Komodo key Komodo rejects** (the brief's settled point):
    - A connection goes to *needs reconnect* with `komodo_key_rejected` and reconnects through consent. An API key becomes *dead* (create a new one; there is no consent for keys).
    - It acts only if the rejected key is still the current one (R1).
    - A key that Komodo no longer knows, deleted from the pending list, counts as done.
11. **Pending deletions:** keys of revoked, dead, replaced or never-exchanged credentials are deleted with the JWT of the user's next sign-in or consent.
    - A key Komodo says is another user's (403) is dropped with a warning, as is one refused more than 10 times.
    - A key that can't even be queued is named in the log (its id, never its secret).
12. **Komodo's per-IP auth rate limiter** sees only the gateway's address. Komogentic limits sign-ins below it (3 a minute per username; per address 4 in 15 s and 5 a minute, IPv6 per /48), never marks a credential dead on a 429, and refuses dead credentials without calling Komodo. The README suggests raising `KOMODO_AUTH_RATE_LIMIT_MAX_ATTEMPTS` for a team.
13. **Allow on the consent page needs no recent password,** unlike Kumbu²'s remembered sessions. Kumbu²'s password window is always open in a normal session, and Komogentic has only normal sessions (30 min idle, 12 h).
14. **Trusted proxy:** kept as Kumbu²'s (any peer is trusted only with `Komogentic:Proxy:Trusted`, rightmost `X-Forwarded-For`). It now requires a public URL, and the public URL is required in Production. Docker assigns the proxy's address, so it can't be pinned.
15. **The audit log** is a log category `Komogentic.Audit`, one line per tool call in every case, also when cancelled, failed or refused for read-only. It records user, credential kind and id and name, client, tool, canonical stack and outcome, without secrets or log content.
16. **Scopes:** a grant asking for `komodo:read` without `komodo:operate` gets the four read tools only. Deploy and restart are hidden from the list and refused on call; the name in the request is checked too, so the filter fails closed.
17. **Names and expiries** of connections and keys: 1–60 characters, unique among the user's live ones, case-insensitive; 30, 90, 365 days or never. The Komodo key is named `komogentic/<name>` with the same expiry.
18. **The web app without Tailwind and openapi-fetch:** a few CSS rules and a small `fetch` wrapper; every remaining dependency is one Kumbu² uses.
19. **One server project** (`Komogentic.Server`), folders per concern.
20. **A refused revoke JWT:** if Komodo rejects the JWT while a revoke deletes the Komodo key, the revoke stands (204), the key is queued and the session ends.
